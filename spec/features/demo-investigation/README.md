# Feature: Demo Investigation

## Summary

The anonymous /demo route: a visitor arrives with a question from datatug.ai or datatug.io and watches DataTug answer it from a real in-browser run of a saved cross-source query, with an inspectable trace and no AI.

## Problem

A visitor arriving from the DataTug sites needs to see DataTug answer a real question before anything asks her to sign in. Today the web app has no anonymous entry: the browser chat needs a configured AI provider, reads only Chinook, and shows no account of how an answer was assembled. The hero question ("Which countries buy the most music relative to their population?") needs three sources (Chinook invoices, a country alias table, World Bank population), so it also exercises the browser DTQL engine's cross-source path.

## Behavior

### Entry and hand-off

#### REQ: demo-route

`/demo` is an anonymous route registered before the catch-all, with no auth guard and no sign-in prompt before the answer. It is registered only when the `demoRoute` flag (`datatugDemoConfig.enabled`, per environment file) is on; it is on in development and e2e builds and its production default is a single line in `environment.prod.ts`. The page's library code is lazy-loaded; the eager shell passes the demo configuration as route data.

#### REQ: handoff-contract

The hand-off is `/demo?scenario=<id>&q=<question>&lang=<en|ru>`. The eager shell captures the query string into `sessionStorage` and removes it from the address bar before analytics and the router run (leaving it in place if it cannot be stored). The page consumes the stored hand-off exactly once, so a reload never starts a second run. `q` is cut at 1000 UTF-8 bytes. Unknown values are ignored, never an error. A question that matches a scenario's known wording runs that scenario without `scenario`. `sales-per-capita` is accepted as an alias of `countries-music-per-capita`.

#### REQ: no-free-form

A missing or unknown scenario, `scenario=custom`, a scenario this release cannot run, or a question that matches nothing shows the question as given, the three curated scenarios, and an honest note that free-form questions need the next release. Nothing runs, nothing is fetched, and no AI is called. Only the first scenario can run in this release; the other two are listed as not in this release.

### Knowledge and data

#### REQ: versioned-bundle

The saved query, the project's Chinook schema, the `Country` entity mappings and the data attribution are loaded from a static bundle generated by `tools/demo-bundle/generate.mjs` from one pinned commit of `datatug/datatug-demo-projects` (`tools/demo-bundle/pin.json`). `pnpm demo:bundle:check` fails when the committed bundle or data files differ from their recorded hashes or the pin; with `--source` it also rebuilds from the pinned commit and fails on any difference. Attribution for World Bank Open Data (CC BY 4.0), the Chinook database (MIT) and GeoNames (CC BY 4.0) travels with the data and is shown in the page.

#### REQ: real-execution

The answer comes from `runFederatedQuery` running the saved cross-source query in a browser worker: the join of three sources, the grouping and the sales-per-million arithmetic are computed by the browser DTQL engine, never precomputed. No AI is called on this path. The data source is configured per environment: the demo project's OVDB server (development, e2e) or static JSON published with the app (the production default until hosted OVDB carries the `geo` database). The static adapter answers the OVDB paging protocol from files whose rows are generated from the same pinned commit, so the engine's input is the same rows.

### Trace and result

#### REQ: investigation-trace

Each run records a trace: one step per check or query that really ran, emitted when it finishes (a long step is emitted `running` first), with a status, a message key and parameters (never model prose), the decision mechanism, a provenance class, expandable evidence (tables and fields chosen, mapping counts, sources, row counts observed in this run, timing, the DTQL) and no chain of thought. Counts in a message are computed from the rows read in this run. Steps the product does not do yet (MeaningGraph service, a directory of sources, Jev) are absent or say what actually happened; a part of a step that is not connected is marked Preview. The trace is stored with the session through the chat session store (DALgo IndexedDB, database version 3, collection `ChatTraceSteps`, migrated in place from version 2) and replays on reload without running anything.

#### REQ: result-presentation

The result is an AG Grid with the shared DataTug theme (v36 Theming API, driven by the app's Ionic variables) with sorting and filtering, totals and rates rounded for display with one half-to-even rule, and a bar chart of sales per million people (top ten plus the country with the largest total at its true rank). Hovering a grid row or a chart bar highlights the other.

#### REQ: computed-observations

The follow-up "What can you say about this data?" adds an insight step and an observations block computed deterministically from the result rows: the largest total against its per-person rank, the leader and whether it is a near tie, and whether small countries dominate the top. Every observation names the countries it rests on and can highlight them in the grid and chart. The block says it was computed from the result and no AI wrote it.

### Edges, language and ownership

#### REQ: honest-edges

A run shows loading and a slow-network note, an unreachable data source (clear message, a retry, the failed step visible), a failure, an empty result and an interrupted run restored after a reload, each with a way to retry. A browser that cannot store sessions still runs the demo and says nothing was saved.

#### REQ: language

`lang=ru` renders the demo's own text (page, trace, observations, number formats) in Russian; the app has no i18n mechanism, so the demo carries its own English and Russian dictionary with identical keys and placeholders. The question is shown as given. The choice is remembered and can be switched on the page.

#### REQ: keep-call-to-action

After the follow-up result the page offers "Keep this investigation and make it yours", which opens the existing sign-in flow and returns to `/demo`. The copy states that saving to an account is a later release; the investigation stays in this browser until then. Nothing is labelled as working that is not.

### Local stack and tests

#### REQ: local-stack

`pnpm demo:up` starts or attaches to what the demo needs locally (the demo project's OVDB server, a CORS shim in front of it, the web dev server), prints a status table and the demo URL, and `pnpm demo:down` stops only what it started. The Playwright `demo` project (`pnpm demo:e2e`) runs against that stack with no interception of the data path, skips with the command to start the stack when it is not running, and makes no request to a host other than localhost.

## Acceptance Criteria

### AC: canonical-handoff

Given the stack is running, when a visitor opens `/demo?scenario=countries-music-per-capita&q=Which countries buy the most music relative to their population?&lang=en`, then the address bar reads `/demo`, the question is shown, the trace steps appear in order, the grid shows 24 rows with Ireland first at 8.32 and the USA at 1.53, the chart shows the top ten and the USA at rank 17, and no request leaves localhost.

### AC: trace-is-real

Given a completed run, then the reconciliation step reads "21 of 24 Chinook countries match the reference names exactly; 3 needed the project's alias table" and "24 of 24" from rows read in that run, the execute step reports 412 invoices, 24 aliases and 216 population records and that the result adds up to the invoices' total, the meaning step carries a Preview marker, no step has tokens or a model mechanism, and the trace says no AI was used.

### AC: observations-link-rows

Given the result, when the visitor asks the follow-up, then three observations appear (the USA has the largest total but ranks number 17 per person; Ireland leads, just ahead of Czech Republic; nine of the ten countries with the most sales per person have under 20 million people), and "Show the rows" highlights exactly the rows and bars each rests on.

### AC: reload-restores

Given a finished investigation with its follow-up, when the page is reloaded, then the question, every trace step, the grid, the chart and the observations are restored, the address stays `/demo`, and no data source is contacted.

### AC: unknown-scenario

Given `?scenario=something-else&q=How many invoices were paid in 2012?`, then the question and the three scenarios are shown with the note that free-form questions need the next release, and no source is contacted.

### AC: source-down

Given the data source is unreachable, then the trace ends in a failed step, the page says the source is not reachable with a retry, no grid is shown, the failure survives a reload, and a retry after the source returns completes the run.

### AC: static-source-parity

Given the static data source, then the same query returns the same 24 rows in the same order as with the OVDB server.

### AC: bundle-drift

Given a data file whose hash differs from the bundle, a pin that differs from the bundle's commit, or a data file the bundle does not list, then `demo:bundle:check` exits non-zero and says to regenerate.

### AC: russian

Given `lang=ru`, then the page, the trace and the observations render in Russian, plural forms agree with their numbers, and the question appears as given.

### AC: flag-off

Given a build whose `demoRoute` flag is off, then `/demo` is not a registered route and the hand-off is not captured.
