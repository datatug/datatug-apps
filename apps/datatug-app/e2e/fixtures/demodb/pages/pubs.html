Explore SQLite in DataTug

Known limits.

  • Editing needs exactly one primary-key column. 4 of 11 tables here have a composite key or none, so they open read-only: discounts, roysched, sales, titleauthor.
  • Views are not listed: the local SQLite browser shows the 11 tables only, not the 1 views. The schema pages on this site list them.
  • A table opens with its first 100 rows. There is no paging yet.

Explore PostgreSQL in DataTug

Read-only.

  • Explore PostgreSQL in DataTug is read-only by design: you can browse tables and records, but nothing can be edited, deleted or reset.
  • It reads the hosted PostgreSQL copy through the public OpenVaultDB server with read-only DTQL queries, never the database directly.
  • A table opens with its first 100 rows. There is no paging yet.
  • To change data, use the editable local SQLite copy that Explore SQLite in DataTug opens in your browser.

Formats not offered for Pubs

  • SQL Server scriptPlanned: Microsoft's instpubs.sql is retained in the provider repository, but the pinned fixture normalises its dates and defaults, so the original script is not the pinned data. DemoDB's SQL Server script will be generated by the DataTug SQL-script exporter (dialect mssql, in review and not yet released) from the pinned SQLite fixture, and is published only after it has loaded and verified on a real SQL Server.
  • Oracle scriptPlanned: The DataTug SQL-script exporter has no Oracle dialect yet, so DemoDB has no generated Oracle script for the pinned SQLite fixture, and no Oracle Database has loaded one. Nothing unverified is published.
