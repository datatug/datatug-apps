## Immutable runtime capability

A configured `bounds.runtime.readProfile: bounded-immutable/1` selects ordinary POST DTQL reads. Every declared database supplies the exact provider revision and native source SHA256; initial serving and manifest SHA256 pins are omitted together or supplied together. Each response must supply all four matching pins before its rows are decoded. First reads of one database are serialized. Saved definitions keep all four pins and a descriptive page-history receipt; this configuration and receipt never grant semantic or publication eligibility.

Each action reads one explicit page per source with a limit no greater than 1000 and the remaining row allowance. No snapshot headers, caller ordering, automatic drain or sentinel request reaches the runtime. DALgo only pages the already accepted local cache. An explicit next-source-page action retains the original 10-second monotonic deadline, cumulative 5MiB decoded-response budget, separate 5MiB materialized output budget, 1000 selected users, 50 ROR/100 place identifiers, and 5000 intermediate/final rows. Errors and cached HTTP response bodies pass the same streaming guard. Expiry prevents source continuation while leaving stored local result pages readable; closing or a hard worker deadline removes the run's explicitly owned databases.

A full page is possibly-more. A skipped offset or a changed parent-filter context cannot establish complete coverage. Truncated dependencies preserve observed raw rows but mark absence and cardinality as unresolved rather than definitive unmatched, ambiguous or multiplied totals. A later parent page invalidates downstream completeness; a changed parent-filter context requires a new explicit run. Saving runtime pins checks the exact executed source/contract/query/projection/bounds identity and rejects changed or incomplete pin coverage. Reopening does not fetch metadata or data.

Deterministic transport, worker/DALgo and zoneless component tests prove these mechanics. The current Directory metadata does not yet provide final admitted runtime configuration, and production discovery/saved-scenario execution remains closed. Live browser-to-driver cancellation, deployed CORS/pins/routes, final canonical admission and J1–J6 network evidence remain pending. The wider ROR location-to-Geo/admin1 journey also needs an approved execution projection: the retained ROR model declares integer `locations.geonames_id`, Geo declares string `geonames_places.geonameid`, and admin1 uses a composed country/admin key. This capability does not introduce numeric/string coercion, concatenation, a transform language or a new meaning.
