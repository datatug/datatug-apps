# Public Data Fabric W1 preparation

The project `public-data` route reads immutable canonical Directory, ModelSpec and MeaningGraph indexes, loads existing configured project sources and resolves an exact source field through explicit canonical provider and recordset-to-model mappings, inspects a scoped representation attachment and saves its pins through the existing query service. A metadata cache is disposable and keyed by repository, revision, path and checksum. Discovery admits at most 96 references, depth 8 and an aggregate 2MiB, rejects cycles, redirects, duplicate JSON keys and aliases of consumed structural fields, wrong hashes and missing scoped model/binding properties.

The reviewed schema1 consumer checks provider-local references against the outer immutable Directory commit and external references against exact registry pins. It checks binding/property scope, generator provenance, bridge/key artifact hashes, native namespace and bridge collisions. These checks establish byte/shape compatibility, never semantic acceptance. Schema copied from `openvaultdb/ovdb` main `aec07d17be1e074210acefddb858363ce7777704`; native schema2 is still a separate unfrozen proposal.

Production discovery and all saved PublicDataScenario execution remain closed pending reviewed canonical Directory/provider companion publication and fresh admission. Serialized `eligible` flags cannot authorize execution. The ordinary explicit bounded executor can be tested independently; it does not certify a semantic source mapping. No fixture switch or scenario catalogue enables production discovery.

The bounded transport first selects at most 1000 user rows, then queries only their exact keys through the installed DALgo `In` dialect. It caps distinct keys at 100 places or 50 ROR IDs, results at 5000, aggregate response bytes at 5MiB and the run at 10 seconds. It refuses undeclared origins, redirects, ignored filters, expired/changing snapshots and unsafe pagination, releases snapshots and supports cancellation. Worker termination enforces the wall deadline even during synchronous work. No full static dataset fallback is available in this mode. Results keep raw values, distinct NULL/empty/invalid/unmatched/ambiguous counts and affiliation grain; an explicit ROR:URL syntax validator prevents requests for malformed IDs while keeping raw invalid inputs; checksum-valid but absent IDs remain unmatched. This syntax support grants no semantic eligibility. Native ROR format/checksum validity is separate from membership, with inactive/withdrawn snapshot status retained.

The primary route selects configured source/table/field metadata without requiring repository hashes or contract JSON. Explicit connection identity or exact upstream repository/revision must resolve to one canonical provider; API bases, host similarities and table names cannot infer provider identity. Recordset modelEntity, physical schema and string field coordinates must match the pinned registry and verified scoped attachment. Missing provenance stays visibly unavailable. Existing HTTPS catalog keys can list configured flat tables without fetching their rows. A deliberate preview button reuses the existing table view; advanced descriptor JSON remains secondary diagnostics. The route connects and explains without querying data. Run is explicit. Result pagination reads already bounded stored output. Save and reopen retain source, canonical index, model, meaning, snapshot, attachment, rights and decision pins. Reopening makes no lookup; changed canonical pins require visible acknowledgement, and publication admission remains required.

Tests use synthetic copies of the reviewed helper fixture, a bounded runtime fixture and service doubles for the full template journey. Byte-pinned actual Directory and ModelSpec indexes separately test configured source service integration, wrong origin/revision/schema/recordset mappings and checksum preservation. They cover configured source/field selection without hash typing, connect, explanation, inspect, explicit run, exceptions, save and reopen; production-unavailable behavior is separate. Existing query-page tests verify reopened pins and reject forged eligibility. These tests prove fixture mechanics, not deployed OVDB filter support or a real published source journey.
